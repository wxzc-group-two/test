# 1. AI建设目标


蜀道安全助手通过大语言模型（Large Language Model，LLM）、知识检索增强生成（Retrieval-Augmented Generation，RAG）以及智能Agent技术，实现企业安全生产场景下的智能化辅助。

AI模块主要解决传统安全管理中：

1. 安全规范查询效率低；
2. 企业安全知识分散；
3. 安全培训内容制作成本高；
4. 隐患分析依赖人工经验。

通过AI技术，实现：

- 安全知识智能问答；
- 企业安全规范精准检索；
- 隐患风险辅助分析；
- 安全考试题目智能生成。


---

# 2. AI整体架构设计


系统采用“大语言模型 + RAG知识库 + Agent智能体”的整体架构。


整体流程：

```
用户

↓

Web前端

↓

后端AI服务接口

↓

AI Agent智能体层

↓

-----------------------

|                     |

RAG知识库          大语言模型

|                     |

企业安全文档       API / 本地模型

```


AI服务主要包含：

|模块|作用|
|-|-|
|安全问答Agent|回答安全生产相关问题|
|知识检索Agent|检索企业安全规范|
|隐患分析Agent|辅助判断隐患风险|
|考试生成Agent|自动生成考试题目|

# 3. 大语言模型选型方案


## 3.1 云端大模型方案


系统支持调用第三方大模型接口。


候选模型：

|模型|特点|适用场景|
|-|-|-|
|DeepSeek|推理能力强、成本较低|快速开发验证|
|通义千问|中文理解能力优秀|企业中文场景|
|智谱GLM|企业服务能力较完善|企业应用|


### 优点

- 无需部署模型环境；
- 接入简单；
- 模型能力较强。


### 缺点

- 需要网络环境；
- 企业数据可能需要上传第三方服务。


适用于：

项目开发阶段和功能验证阶段。


---

## 3.2 本地模型部署方案


为了满足企业数据安全需求，系统支持本地大模型部署。


部署方案：

```
Ollama

+

Qwen2.5

+

GGUF量化模型

```


运行流程：

```
后端服务

↓

Ollama接口

↓

本地大模型

↓

返回生成结果

```


### 优点

- 数据不离开企业环境；
- 无需持续支付API费用；
- 满足私有化部署需求。


### 缺点

- 需要服务器或高性能电脑；
- 推理速度依赖硬件配置。


适用于：

企业正式部署环境。

# 5. RAG知识库方案


## 5.1 使用RAG原因


通用大语言模型存在以下问题：

1. 不了解企业内部安全制度；
2. 无法保证回答完全准确；
3. 容易产生模型幻觉。


因此采用RAG技术，让模型基于企业知识库生成答案。


---

## 5.2 RAG流程


flowchart TD

A[用户输入问题]

-->

B[问题理解]

-->

C[RAG知识检索]

-->

D[调用大模型]

-->

E[生成回答]

-->

F[展示答案和来源]


# 11. 性能优化方案


目标：

AI回答首字响应时间 ≤ 3秒。


优化措施：

## 1. 流式输出

采用SSE技术，实现AI回答实时返回。


## 2. 知识库优化

提前完成：

- 文档解析；
- Embedding计算；
- 向量索引。


## 3. 模型优化

包括：

- Prompt优化；
- 模型量化；
- 合理选择模型规模。


## 4. 缓存优化

缓存：

- 高频安全问题；
- 常用规范查询。
